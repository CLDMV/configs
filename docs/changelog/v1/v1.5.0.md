# `@cldmv/configs` v1.5.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

The ESLint base is now a Node-only layer. Browser globals and Vitest globals are opt-in through two new named exports, and a repository's own `.configs/` files are linted. This only makes the lint stricter where it was silent: code that relied on a browser global, or a test that used `describe` without importing it, now gets a `no-undef` error to fix.

The package also declares its dev toolchain floor in `devEngines`, takes `@cldmv/eslint-plugin-jsonv` 2, and refreshes the dev tools. `fix-headers.json`, `prettier.json`, `prettierignore`, `vitest.config.mjs` and the `cldmv-configs` CLI are unchanged.

---

## ✨ Features

### Node-only ESLint base, with opt-in browser and Vitest globals ([#58](https://github.com/CLDMV/configs/pull/58), fixes [#43](https://github.com/CLDMV/configs/issues/43))

The base used to declare `globals.node` and `globals.browser` for every script, and the Vitest globals for every `tests/**/*.test.vitest.mjs` file, so `window`, `self`, `document` and `name` never tripped `no-undef` in a Node package, and a test that forgot `import { describe, it } from "vitest"` linted clean. For packages built on slothlet, where `self` is a runtime binding that has to be imported, a missing import went unnoticed.

Now:

- The default export declares `globals.node` only.
- `withBrowserGlobals(files?)` returns a block with `globals.browser` for the given files (default: every `**/*.{js,mjs,cjs}` script), for code that really runs in a browser.
- `withVitestGlobals(files?)` returns a block with the Vitest globals, read-only, for the given files (default: `tests/**/*.test.vitest.mjs`). Use it only when the repository's Vitest config sets `test.globals: true`.
- `.configs/**` is no longer ignored, so an unused or unspread import in a repository's own tool configs is reported.

```js
import base, { withBrowserGlobals, withVitestGlobals } from "@cldmv/configs/eslint.config.mjs";

export default [...base, withBrowserGlobals(["src/browser/**/*.mjs"]), withVitestGlobals()];
```

The README's Versioning section counts a change that only makes a tool stricter where it was silent as a minor. The tests lint sample code end to end for each case.

## 🐛 Bug Fixes

### The dev toolchain floor is declared in `devEngines` ([#45](https://github.com/CLDMV/configs/pull/45))

configs only runs as a consuming repository's dev tooling, so it still declares no runtime `engines`. The 22.22.0 floor that Vitest 5 needs now goes in `devEngines` (`onFail: "error"`), and the CI and publish workflows test from Node.js 22.22.0 instead of 22.12.0.

## Upgrade notes

- After updating, run the repository's `lint`. Expect `no-undef` for browser globals in Node code (import what you meant, or add `withBrowserGlobals()` for real browser files) and for Vitest globals in tests (import them from `vitest`, or add `withVitestGlobals()` if the Vitest config sets `test.globals: true`). Expect lint findings in `.configs/` files too.
- Nothing else changes: the other configs and the CLI behave as in [v1.4.0](./v1.4.0.md).
