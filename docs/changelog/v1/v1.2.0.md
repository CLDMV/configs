# @cldmv/configs v1.2.0 Changelog

**Release Date**: October 2026
**Release Type**: Minor

---

## Overview

The shared `fix-headers.json` now sets `margin: 1`, so fix-headers leaves one blank line between a file header and the code after it. fix-headers 2.1.0 introduced the `margin` option with a default of two blank lines, and Prettier collapses two blank lines to one, so every repository that ran both tools saw the two fight over the same line on every run. With `margin: 1` the header layout matches what Prettier keeps, and a header pass followed by a format pass is stable.

This is a change to what fix-headers writes for every repository that extends the shared config on fix-headers 2.1.0 or later, which this package's own versioning policy classes as a major change; it shipped as a minor release. In practice it keeps the one-blank-line layout those repositories already had before fix-headers 2.1.0.

---

## 💥 Breaking Changes

### `margin: 1` in the shared fix-headers config ([#7](https://github.com/CLDMV/configs/pull/7))

Despite being a minor release, this changes the output of fix-headers 2.1.0 or later for every extending repository: the header is followed by one blank line instead of fix-headers' default of two. Repositories on fix-headers 2.0.x are unaffected, since that release has no `margin` option and ignores the key.

## 📚 Documentation

- The README shows `margin: 1` in the config listing and explains it in the key table ([#7](https://github.com/CLDMV/configs/pull/7)).

## 🔧 Dependencies

- `@cldmv/fix-headers` `^1.3.12` → `^2.1.0` ([#5](https://github.com/CLDMV/configs/pull/5), dev-only), so the repository's own header pass understands `extends`, the date options and `margin`.

---

## Upgrade notes

- A repository that runs Prettier after fix-headers needs no change; the next header pass stops adding a second blank line that Prettier then removes.
- A repository that wants fix-headers' two-line default back sets `"margin": 2` in its own fix-headers config, which overrides the shared value.
