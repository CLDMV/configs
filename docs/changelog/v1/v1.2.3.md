**Release Date**: October 2026

## Overview

`@cldmv/fix-headers` moves to 2.1.4, and re-running the header pass with the repository's own `fix-headers.json` restamped the headers of 37 files — the first full pass under fix-headers 2.x since the repository moved to it in [v1.2.0](./v1.2.0.md). Only header comments in repository-internal files changed (the ESLint and vitest configs, the pre-commit installer, Dependabot config, every workflow and the tests). The published files — `fix-headers.json`, `README.md` and `LICENSE` — and every shipped setting are unchanged.

---

## 🔧 CI & tooling

### File headers restamped under fix-headers 2.1.4 ([#12](https://github.com/CLDMV/configs/pull/12))

The 37 restamped headers changed in three ways:

- **ISO 8601 dates.** Every `@Date` and `@Last modified time` is now written in git's `%aI` form (`2026-09-28T21:22:20-07:00`) instead of `2026-09-28 21:22:20 -07:00`, as the shared config's `normalizeDateFormat` asks.
- **Corrected `@Date` epochs.** In 23 of the 37 headers — `.github/dependabot.yml` and 22 of the 28 workflow files, whose headers came from the `CLDMV/.github` templates — the Unix timestamp in parentheses did not match the date written beside it (for example `2026-05-20 00:00:00 -07:00 (1779606000)`, where 1779606000 is 24 May). fix-headers kept the written date and rewrote the timestamp to match it (`1779260400`).
- **Header framing.** Each header gained an empty comment line just inside its opening and just before its closing (`/**` then ` *`, or a bare `#` in YAML), fix-headers' default `spacing` of one, while the single blank line after the header comes from the `margin: 1` that the repository's own `fix-headers.json` sets.

`@Last modified time` was updated on every restamped file, as `forceLastModifiedAuthorUpdate` asks.
