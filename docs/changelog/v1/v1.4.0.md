# `@cldmv/configs` v1.4.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/1.4.0`

---

## Overview

`vitest.config.mjs` gains a named export, `devCondition()`, that builds the Vitest settings a CLDMV library needs to run its tests against `src/` through its `<pkg>-dev` export condition. Every library had been copying the same three settings by hand, and the copies set the worker flag through `test.nodeOptions`, which is not a Vitest option, so Vitest's worker processes never received the condition. `devCondition()` puts it in `test.execArgv`, which does reach them.

The default export of `vitest.config.mjs` is unchanged, as are `fix-headers.json`, `prettier.json`, `prettierignore`, `eslint.config.mjs` and the `cldmv-configs` CLI. The rest of the release is dependency updates.

---

## ✨ Features

### `devCondition()` for the `<pkg>-dev` export condition ([#39](https://github.com/CLDMV/configs/pull/39))

A CLDMV library's `exports` carries a `<pkg>-dev` condition that points `.` at `src/` instead of `dist/`. Running the tests against `src/` takes that condition in three places, and `devCondition()` returns all three as a partial Vitest config to merge with `mergeConfig`:

| Setting                  | Value                                                              | Why                                                                                                                                          |
| ------------------------ | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `resolve.conditions`     | the condition, then `module`, `browser`, `development\|production` | Vite's resolver picks `src/` for imports in test files; setting it replaces Vite's defaults, so they follow                                  |
| `ssr.resolve.conditions` | the condition, then `module`, `node`, `development\|production`    | The same for Vite's server-side resolver, which Vitest uses for Node tests                                                                   |
| `test.execArgv`          | `--conditions=<name>`                                              | Vitest's worker processes start with the condition, so Node's own resolver (a `require()`, or anything loaded outside Vite) picks `src/` too |

```js
import { defineConfig, mergeConfig } from "vitest/config";
import base, { devCondition } from "@cldmv/configs/vitest.config.mjs";

export default mergeConfig(
	mergeConfig(base, devCondition({ root: new URL("..", import.meta.url) })),
	defineConfig({ test: { coverage: { include: ["src/**"] } } })
);
```

The argument is the condition name (`devCondition("wisp-dev")`) or `{ name, root }`. Without a name, the condition is read from `<root>/package.json`, where `root` is a path or a file URL and defaults to the current directory: the one condition ending in `-dev` on the `.` export, otherwise the unscoped package name plus `-dev`. More than one `-dev` condition, or no condition and no package name, throws instead of guessing.

Vite's default client and server conditions are also exported as `VITE_CLIENT_CONDITIONS` and `VITE_SERVER_CONDITIONS`. They are copied rather than imported, so `vitest.config.mjs` still imports only Node built-ins and needs nothing installed; a test checks the copies against the installed Vite.

**If your repository copied these settings by hand**, the `test.nodeOptions` entry never did anything. Replace the three settings with `devCondition()`, or at least move the flag to `test.execArgv`. A new test spawns Vitest with the merged config and checks that the flag reaches the worker's `process.execArgv`.

## 🔒 Security & supply chain

- Vite moves from 8.3.2 to 8.3.5 in this repository's install, clearing its Dependabot alert and superseding Dependabot's [#36](https://github.com/CLDMV/configs/pull/36) and [#38](https://github.com/CLDMV/configs/pull/38) ([#39](https://github.com/CLDMV/configs/pull/39), [#40](https://github.com/CLDMV/configs/pull/40)). Vite is a development dependency here; it is not installed for consumers.
- `overrides` now force `katex` to `>=0.19.1 <1.0.0` (0.16.47 → 0.19.1) and `minimatch` to `^11.0.3` (10.2.6 → 11.0.3), the patched versions, in this repository's own install ([#41](https://github.com/CLDMV/configs/pull/41)). npm ignores the `overrides` of an installed package, so these don't reach consuming repositories. `katex` arrives there through `@eslint/markdown`, one of this package's dependencies, whose `micromark-extension-math` still asks for `^0.16.0`; a repository that wants the patched version carries the same override itself.

- To run tests against `src/` through the `<pkg>-dev` condition, merge `devCondition()` into the repository's Vitest config and delete any hand-copied `resolve.conditions`, `ssr.resolve.conditions` and `test.nodeOptions` entries.
