# @cldmv/configs v1.3.0 Changelog

**Release Date**: October 2026
**Release Type**: Minor
**Branch**: `release/1.3.0`

---

## Overview

The package grows from one shared config to five. It adds `prettier.json` (CLDMV's house Prettier settings), `prettierignore` (the generic Prettier ignore list), `eslint.config.mjs` (the fleet's flat ESLint config) and `vitest.config.mjs` (a base Vitest settings object), published as `@cldmv/configs/prettier.json`, `@cldmv/configs/prettierignore`, `@cldmv/configs/eslint.config.mjs` and `@cldmv/configs/vitest.config.mjs`. A repository extends them from its own `.configs/` files instead of keeping a copy of the same settings that every CLDMV repository already carried. The Prettier values and the ESLint rules are the ones the fleet already uses, so a repository that adopts them sees no change.

The package also gains dependencies. ESLint configs are code, so `eslint.config.mjs` imports the ESLint plugins it configures; those six packages are now regular `dependencies`. `eslint`, `vitest` and the jsonv Prettier plugin are optional peer dependencies, needed only by repositories that use the matching config. Until now the package had no dependencies at all.

`fix-headers.json` is unchanged from v1.2.5.

## ✨ Features

### Shared Prettier config

`prettier.json` sits at the package root, is exposed through `exports` as `./prettier.json`, and is listed in `files`:

| Setting                   | Value                              | Why                                                               |
| ------------------------- | ---------------------------------- | ----------------------------------------------------------------- |
| `useTabs`, `tabWidth`     | `true`, `2`                        | Tab indentation, counted as two columns when measuring width      |
| `printWidth`              | `140`                              | Wide lines keep short call chains and object literals on one line |
| `trailingComma`           | `"none"`                           | No trailing commas                                                |
| `quoteProps`              | `"preserve"`                       | Object-key quoting stays as written                               |
| `bracketSpacing`          | `true`                             | `{ a: 1 }`                                                        |
| `overrides` for `*.xml`   | `printWidth: 300`                  | XML markup does not wrap readably at 140                          |
| `overrides` for `*.md`    | `proseWrap: "preserve"`            | Markdown paragraphs are never re-flowed; one paragraph per line   |
| `overrides` for `*.jsonv` | `parser: "jsonv"`                  | Parse `.jsonv` files with the jsonv plugin                        |
| `plugins`                 | `["@cldmv/prettier-plugin-jsonv"]` | Provides the `jsonv` parser                                       |

A consuming repository creates `.configs/prettier.config.mjs`:

```js
import base from "@cldmv/configs/prettier.json" with { type: "json" };

export default base;
```

and runs Prettier with `--config .configs/prettier.config.mjs`. Prettier fails to start when a config names a plugin that is not installed, so repositories without `.jsonv` files either install the plugin or spread the base and drop `plugins` and the `*.jsonv` override; the README shows both.

### Generic Prettier ignore

`prettierignore` lists `node_modules/`, `dist/`, `build/`, `coverage/`, `tmp/`, `trash/`, `package-lock.json`, `pnpm-lock.yaml`, `*.min.*`, `*.yml` and `*.yaml`, each group with a one-line reason (YAML is four-space CI and forbids tabs; `*.min.*` covers compact generated files). It ends with a marker line for repository-specific paths.

Prettier has no ignore `extends`, so the default is to copy the file to `.prettierignore` and append the repository's own paths below the marker line (nothing to append is fine). Prettier and editors read `.prettierignore` on their own, so the format scripts need no flags; the copy no longer follows later changes to the shared list. The alternative, for a repository with no additions that does not need editor support, is `--ignore-path .gitignore --ignore-path node_modules/@cldmv/configs/prettierignore` in the format scripts.

### ESLint base

`eslint.config.mjs` default-exports the flat config as an array, built with `defineConfig` from `eslint/config`, so a repository spreads it and appends its own blocks:

```js
import base from "@cldmv/configs/eslint.config.mjs";

export default [...base];
```

It carries `@eslint/js` recommended with the `^(_|___.*)$` unused-variable pattern, `sourceType: "commonjs"` for `.js` files, Node and browser globals, the Vitest globals for `tests/**/*.test.vitest.mjs`, `@eslint/json` for JSON, JSONC and JSON5, `@cldmv/eslint-plugin-jsonv` for `.jsonv`, `@eslint/markdown` (with `markdown/no-missing-label-refs` off) and `@eslint/css`, plus the shared ignores. There is no HTML block, which is specific to a few repositories. The blocks are the ones common to the configs of this repository, `fix-headers` and `slothlet-vine`.

### Vitest base

`vitest.config.mjs` default-exports a plain object with no imports: `test.environment` `"node"`, `test.include` `["tests/**/*.test.vitest.{js,mjs,cjs}"]`, and v8 coverage reporting `text`, `json`, `json-summary` and `lcov` into `coverage/`. Coverage `include` globs, thresholds and anything else repository-specific stay local, merged over the base:

```js
import { defineConfig, mergeConfig } from "vitest/config";
import base from "@cldmv/configs/vitest.config.mjs";

export default mergeConfig(base, defineConfig({ test: { coverage: { include: ["src/**"] } } }));
```

`mergeConfig` concatenates arrays, so a repository's own `include` or `coverage.reporter` entries add to the base ones.

### Dependencies and peers

- **Dependencies (new):** `@cldmv/eslint-plugin-jsonv`, `@eslint/css`, `@eslint/js`, `@eslint/json`, `@eslint/markdown` and `globals`, moved from this repository's `devDependencies`. They were installed at their latest releases (`@cldmv/eslint-plugin-jsonv` ^1.0.16, `@eslint/json` ^2.1.1).
- **Optional peers:** `eslint` `^10.0.0` (the `@eslint/js` that the config uses requires ESLint 10), `vitest` `^5.0.0` and `@cldmv/prettier-plugin-jsonv` `^1.1.0`, each marked optional in `peerDependenciesMeta`, so npm neither installs them nor warns when they are missing.

### This repository uses them

`.configs/prettier.config.mjs`, `.configs/eslint.config.mjs` and `.configs/vitest.config.mjs` re-export or merge over the root files, and the repository's own `.prettierignore` is a copy of the published `prettierignore`, which a test keeps from drifting. Linting, formatting and the test suite behave as before.

## 🧪 Tests

- `tests/prettier.test.vitest.mjs` (new) checks every key in `prettier.json` against the options of the installed Prettier, pins the house values and the three overrides, checks that the plugin it names is the declared optional peer, that the repository's own config re-exports it, and that it formats a sample with tabs at the configured width.
- `tests/prettierignore.test.vitest.mjs` (new) pins the ignore patterns in order, requires a comment above each group and the marker line at the end, and checks that the format scripts use the file.
- `tests/eslint.test.vitest.mjs` (new) checks that the export is an array with the ignores, the JSON, JSONC, JSON5, jsonv, Markdown and CSS language blocks and no HTML block, the CommonJS, globals and test-globals blocks, and the markdown rule override, and lints sample code with it.
- `tests/vitest-config.test.vitest.mjs` (new) checks that the export is a plain object with the expected include pattern and v8 coverage settings, that it merges under a repository config with `mergeConfig`, and that the repository's own config builds on it.
- `tests/package.test.vitest.mjs` expects the five configs in the packed tarball and as exports, imports them by their public specifiers, and checks the dependency and optional-peer lists.
- `tests/configs.test.vitest.mjs` requires `prettier.json` among the published configs.

## Upgrade notes

- No change to `fix-headers.json`: drop-in for v1.2.5. Extending repositories see no difference in fix-headers output.
- Installing `@cldmv/configs` now installs the six ESLint plugin packages as dependencies, whichever config a repository uses. `eslint` itself is not installed for you; repositories that use `eslint.config.mjs` install ESLint 10.
- To adopt a config, add the matching `.configs/` file shown above and point the tool's npm script at it. A repository with `.jsonv` files also installs `@cldmv/prettier-plugin-jsonv`.
